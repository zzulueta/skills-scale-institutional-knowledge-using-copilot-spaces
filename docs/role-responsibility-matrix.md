# Role Responsibility Matrix

## Purpose
This matrix clarifies who is responsible, accountable, consulted, and informed (RACI) for common project activities. Use it to reduce ambiguity about ownership and ensure the right people are involved at the right time.

---

## RACI Legend
- **R (Responsible)**: Does the work to complete the activity
- **A (Accountable)**: Has final approval and accountability for the outcome (only one A per activity)
- **C (Consulted)**: Provides input and feedback before decisions or actions
- **I (Informed)**: Kept informed of progress and outcomes

---

## Activity Responsibility Mapping

### Define success metrics
- **Accountable**: Product Manager
- **Responsible**: Product Manager, Business Analyst
- **Consulted**: Project Manager, Developers, UX Designer
- **Informed**: External Stakeholder

### Prioritize backlog
- **Accountable**: Product Manager
- **Responsible**: Product Manager
- **Consulted**: Project Manager, Developers, Business Analyst, UX Designer
- **Informed**: External Stakeholder

### Implement feature code
- **Accountable**: Tech Lead / Senior Developer
- **Responsible**: Developers
- **Consulted**: UX Designer, Business Analyst, DevOps Engineer
- **Informed**: Project Manager, Product Manager

### Write tests
- **Accountable**: Tech Lead / Senior Developer
- **Responsible**: Developers, QA Engineers
- **Consulted**: Business Analyst (for test scenarios)
- **Informed**: Project Manager

### Create release notes
- **Accountable**: Product Manager
- **Responsible**: Product Manager, Project Manager
- **Consulted**: Developers, Customer Support
- **Informed**: External Stakeholder

### Incident response
- **Accountable**: Project Manager (coordination), DevOps Engineer (technical resolution)
- **Responsible**: DevOps Engineer, Developers (on-call rotation)
- **Consulted**: Customer Support (for user impact), Product Manager (for prioritization)
- **Informed**: External Stakeholder (if high severity)

### Run usability tests
- **Accountable**: UX Designer
- **Responsible**: UX Designer
- **Consulted**: Product Manager, Business Analyst
- **Informed**: Developers, Project Manager

### Set up CI/CD pipelines
- **Accountable**: DevOps Engineer
- **Responsible**: DevOps Engineer
- **Consulted**: Developers, QA Engineers
- **Informed**: Project Manager

### Triage support tickets
- **Accountable**: Customer Support Lead
- **Responsible**: Customer Support
- **Consulted**: QA Engineers (for bug verification), Product Manager (for prioritization)
- **Informed**: Project Manager, Developers (for escalated bugs)

---

## How to use this matrix
- Reference this matrix when planning activities to ensure all roles are clear.
- Identify the "A" (Accountable) role when escalating blockers or decisions.
- Adapt roles and responsibilities to fit your project's specific structure.
- Keep this matrix updated if roles or team structure changes.
